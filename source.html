What we changed

Two forks do the work. MLX gained the kernels and the transport; Exo gained the model's serving path, the cache and the scheduler.

CosineAI/mlx

The MLX fork

Fused attention kernel for the M5 GPU
A FlashAttention-style tiled kernel for the model's latent attention that uses the M5 matrix accelerator and never stores the score matrix. 97 to 104 TFLOPS per Mac against 43 for MLX's default path; a plain matrix multiply reaches 121.
Key chunking
The kernel walks the keys in cache-sized chunks. Bit-identical output, 96.9 to 103.5 TFLOPS, and 16.9 to 18.5 tokens/s on the 128k workload.
Block-sparse attention
The kernel accepts a list of 32-key blocks per 64 queries and skips the rest. At one eighth of the older keys it runs about 1.9x faster, selector included.
Attention that returns its normaliser
The kernel can return the log-sum-exp alongside the output, so machines that each hold a slice of the keys can combine their partial results exactly.
RDMA all-reduce over the Thunderbolt mesh
Collectives between the six Macs go over a full RDMA mesh. A prompt chunk makes 122 reductions of 56 MiB at about 5.5 ms each.
CosineAI/exo-wave

The Exo fork

Tensor-parallel serving of the model
All six Macs work on every token, splitting attention heads and experts, instead of passing activations down a pipeline.
One cache per session, never copied
Sessions join and leave a batch without their keys being copied, and a session's saved cache is the one it generates into. The cache has a 120 GB budget per Mac and spills to SSD.
Prompt scheduler
Prompts are processed in 4,096-token chunks, shortest first with ageing, and each chunk's layers are sliced so running sessions keep decoding in between. Worst stalls fell from about 11 s to 4 to 6 s.
Decode split by keys
When several sessions decode together, the Macs split the cached keys between them instead of the heads.
Communication overlapped with compute
Each layer's cross-machine reduce is pipelined in 2,048-token pieces: about +2%.
Prompt-lookup speculation for a lone stream
A session decoding on its own guesses up to 16 tokens copied from its context: 1.6 to 1.8x single-stream decode.
Block-sparse prompt attention
For each block of 64 queries, two are scored exactly and their attention picks which older key blocks to keep. Prompt speed at 100k went from 717 to 1,238 tokens/s, and the long-context replay from 13.87 to 21.23 tokens/s.

Outside the code

  • Cooling. The Macs throttled about a minute into full load. Reversing the fan direction removed it: 11.9 to 16.9 tokens/s on an identical configuration.
  • 4-bit weights. Moving from 8-bit to 4-bit freed the memory that 16 long sessions need. Top-1 disagreement with 8-bit on agent trajectories was 2.2%, against 1.1% between two 8-bit runs.

What to keep in mind

  • Block-sparse attention is an approximation. Against exact attention on 16 trajectories at 100k, top-1 disagreement was 1.86% with a noise floor of 0.78%, and no decisive token flipped. It has not yet had a task-level evaluation. It is inactive below 32k of context, so the light agentic chat and short coding results use exact attention.
  • The short coding run stalls on both builds. The longest gap between tokens was 106 s on our forks and 214 s on stock.
  • Stock means the install Wave ships: Exo revision edc34b97 with its own MLX 0.32.4 and no tuning. We added the 4-bit model card so it could load the model.
  • Tried and set aside: skipping attention layers, merging old keys, 8-bit resting caches, reusing a compacted session's keys at shifted positions, and holding each session's keys on a single Mac.
